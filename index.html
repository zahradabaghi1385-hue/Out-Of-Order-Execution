مشکل اجرای ترتیبیThe problem with in-order execution

lw  x1, 0(x2)
add x3, x1, x4
sub x5, x6, x7
and x8, x9, x10
  • lw: دریافت داده از حافظهlw: fetches data from memory
  • add: وابسته به نتیجهٔ lwadd: depends on the result of lw
  • sub و and: مستقل از lwsub and and: independent of lw

مشکل: انتظار یک دستور می‌تواند مانع اجرای دستورهای مستقل شود.Problem: one waiting instruction can block independent ones.

چرا اجرای ترتیبی مشکل‌ساز است؟Why is in-order a problem?lw ممکن است چند سیکل کلاک طول بکشد و add باید منتظر بماند؛ اما sub و and مستقل‌اند. در اجرای ترتیبی این انتظار خط لوله را متوقف می‌کند (Pipeline Stall). هدف OOO: پر کردن زمان انتظار با دستورهای مستقل.lw may take several clock cycles and add must wait, yet sub and and are independent. In-order, this wait stalls the pipeline. OOO goal: fill the waiting time with independent instructions.

ایدهٔ اصلی OOOThe main idea of OOO

  • دریافت دستورها به ترتیب برنامهFetch instructions in program order
  • اجرای دستورهای آماده، مستقل از ترتیب اولیهExecute ready instructions, regardless of the original order
  • حفظ وابستگی‌های واقعی میان دستورهاPreserve the true dependencies between instructions
  • تأیید نهایی نتایج به ترتیب برنامهCommit the results in program order

هدف: کاهش زمان انتظار و استفادهٔ بهتر از واحدهای اجراییGoal: less waiting and better use of the execution units

نحوهٔ انتخاب دستور برای اجراHow an instruction is pickedپردازنده وضعیت دستورهای منتظر را بررسی می‌کند و دستوری را برمی‌دارد که عملوندهایش آماده و واحد اجرایی مناسبش آزاد باشد. ترتیب اجرا ممکن است عوض شود، اما وابستگی‌های واقعی رعایت می‌شوند و نتایج به ترتیب برنامه تأیید می‌شوند.The CPU checks the waiting instructions and picks one whose operands are ready and whose execution unit is free. Execution order may change, but true dependencies are respected and results commit in program order.

4. Dispatchارسال دستورSend the instruction
5. Issue / Scheduleانتخاب دستور آمادهPick a ready instruction

توضیح مراحل مهمKey stages explainedRename: نگاشت ثبات منطقی به فیزیکی. Issue: بررسی آماده‌بودن عملوندها و انتخاب دستور. Write Back: نتیجه برای دستورهای وابسته در دسترس می‌شود. Commit: تأیید نتایج به ترتیب برنامه. مراحل دقیق ممکن است در پردازنده‌های مختلف فرق کند.Rename: map logical to physical registers. Issue: check operands and pick an instruction. Write Back: result becomes available to dependents. Commit: results finalized in program order. Exact stages vary between processors.

تفاوت ترتیب اجرا و ترتیب برنامهExecution order vs. program order

Program OrderProgram Orderترتیب اصلی دستورها در برنامهoriginal order in the program
Execution OrderExecution Orderترتیبی که دستورها واقعاً اجرا می‌شوندorder they actually run
Commit OrderCommit Orderترتیب تأیید نهایی نتایجorder results are finalized

در OOO، ترتیب اجرا می‌تواند تغییر کند؛ اما ترتیب Commit حفظ می‌شود.In OOO the execution order can change, but the Commit order is preserved.

مثال کاربردیA practical exampleدستور اول داده را از حافظه می‌گیرد و دستور دوم محاسبهٔ مستقلی دارد. اگر دریافت داده طول بکشد، دستور دوم زودتر اجرا می‌شود، اما تأیید نتایج به ترتیب اصلی می‌ماند. تغییر ترتیب اجرا، نتیجهٔ منطقی برنامه را عوض نمی‌کند.The first instruction loads from memory; the second is an independent computation. If the load is slow, the second runs earlier, yet results still commit in the original order. Reordering execution does not change the program’s logical result.

وابستگی دستورهاInstruction dependencies

RAW · Read After WriteRAW · Read After Writeوابستگی واقعی داده؛ دستور بعدی به نتیجهٔ قبلی نیاز دارد و باید منتظرش بماند.True data dependency; the next instruction needs the previous result and must wait for it.
WAR · Write After ReadWAR · Write After Readوابستگی نامی؛ دستور دوم نباید مقدار قدیمی را پیش از خواندن اولی بازنویسی کند. تغییر نام ثبات آن را برطرف می‌کند.Name dependency; the second must not overwrite the old value before the first reads it. Renaming fixes it.
WAW · Write After WriteWAW · Write After Writeوابستگی نامی؛ دو دستور در یک ثبات مقصد می‌نویسند و ترتیب ثبت نتایج باید حفظ شود.Name dependency; two instructions write the same destination, so result order must be kept.

Register Renaming وابستگی‌های نامی را برطرف می‌کند، اما RAW واقعی را حفظ می‌کند.Register Renaming removes name dependencies but keeps the true RAW dependency.

تغییر نام ثبات‌ها (Register Renaming)Register Renaming

I1: add x1, x2, x3
I2: sub x4, x1, x5
I3: add x1, x6, x7
I1: add p10, x2, x3
I2: sub p11, p10, x5
I3: add p12, x6, x7
  • x1: نام منطقی ثبات؛ p10، p11، p12: ثبات‌های فیزیکیx1: logical register; p10, p11, p12: physical registers
تغییر نام چگونه کار می‌کند؟How does renaming work?I1 و I3 هر دو در x1 می‌نویسند (WAW). پس از تغییر نام، نتایج در p10 و p12 می‌روند و I3 منتظر I1 نمی‌ماند؛ ولی I2 همچنان به نتیجهٔ I1 وابسته است.I1 and I3 both write x1 (WAW). After renaming they go to p10 and p12, so I3 need not wait for I1; I2 still depends on I1’s result.

ارتباط میان اجزاHow the parts work togetherRename Table نگاشت را مشخص می‌کند؛ دستورها در Reservation Stations منتظر عملوند می‌مانند؛ واحدهای اجرایی نتیجه را می‌سازند؛ ROB ترتیب Commit را مدیریت می‌کند تا وضعیت معماری درست بماند.The Rename Table sets the mapping; instructions wait in Reservation Stations; execution units produce results; the ROB manages Commit order to keep architectural state correct.

مزایای اجرای خارج از ترتیبBenefits of out-of-order execution

  • کاهش زمان بیکاری واحدهای اجراییLess idle time for the execution units
  • استفاده از زمان انتظار حافظه برای کارهای مستقلUsing memory wait time for independent work
  • افزایش بهره‌برداری از منابع پردازندهBetter use of processor resources
  • بهبود عملکرد بسیاری از برنامه‌های واقعیBetter performance for many real programs
چرا OOO عملکرد را بهتر می‌کند؟Why does OOO improve performance?زمان انتظار برای داده یا آماده‌شدن یک دستور صرف محاسبات مستقل می‌شود. میزان بهبود به نوع برنامه، تعداد دستورهای مستقل و تأخیر حافظه بستگی دارد؛ پس OOO سریع‌تر شدن همهٔ برنامه‌ها را تضمین نمی‌کند.Waiting time is spent on independent work. The gain depends on the program, the number of independent instructions and memory latency, so OOO does not guarantee every program runs faster.

هزینه‌ها و محدودیت‌هاCosts and limitations

  • طراحی سخت‌افزاری پیچیده‌ترMore complex hardware design
  • مصرف انرژی و فضای تراشهٔ بیشترMore power and chip area
  • محدودیت ناشی از وابستگی‌های واقعیA limit imposed by true dependencies
  • احتمال دورریختن کارهای حدسی پس از پیش‌بینی اشتباهSpeculative work may be discarded after a misprediction

OOO سرعت را افزایش می‌دهد، اما تضمین نمی‌کند همهٔ برنامه‌ها سریع‌تر اجرا شوند.OOO increases speed, but does not guarantee every program runs faster.

چرا OOO هزینه دارد؟Why does OOO cost something?به سخت‌افزار پیچیده‌تری برای بررسی وابستگی‌ها، انتخاب دستور آماده و مدیریت نتایج نیاز دارد؛ Reservation Stations و ROB فضای تراشه و انرژی می‌گیرند. نتیجه: عملکرد بهتر، با هزینهٔ سخت‌افزاری و انرژی بیشتر.It needs more complex hardware to check dependencies, pick ready instructions and manage results; Reservation Stations and the ROB use chip area and energy. Result: better performance at a higher hardware and energy cost.

OOO و امنیت پردازندهOOO and processor security

  • اجرای دستورها بر اساس پیش‌بینی پردازندهExecuting instructions based on the CPU’s prediction
  • کنارگذاشتن نتایج معماری در صورت پیش‌بینی اشتباهDiscarding architectural results if the prediction was wrong
  • امکان باقی‌ماندن آثار جانبی ریزمعماری، مانند تغییر وضعیت کشMicroarchitectural side effects may remain, such as cache state
اجرای حدسی چیست؟What is speculative execution?پردازنده پیش از مشخص‌شدن نتیجهٔ یک شرط، مسیر محتمل را پیش‌بینی و اجرا می‌کند. اگر اشتباه باشد، نتایج تأیید نمی‌شوند و به مسیر درست برمی‌گردد؛ اما ممکن است حالت Cache تغییر کرده باشد.Before a branch resolves, the CPU predicts and runs the likely path. If wrong, results are not committed and it returns to the right path, but the Cache state may have changed.
ارتباط با امنیتLink to securityبرخی حملات از همین آثار جانبی برای استنباط اطلاعات حساس استفاده می‌کنند، حتی وقتی نتایج حدسی ثبت نشده‌اند. نمونه‌ها: Spectre و Meltdown.Some attacks use these side effects to infer sensitive data even when speculative results were never committed. Examples: Spectre and Meltdown.

آسیب‌پذیری SpectreThe Spectre vulnerability

Spectre چیست؟What is Spectre?خانواده‌ای از حملات که از پیش‌بینی شاخه و اجرای حدسی برای ایجاد شرایطی استفاده می‌کند که اطلاعات حساس را افشا کند.A family of attacks that abuse branch prediction and speculation to leak sensitive information.
۱. تأثیر بر پیش‌بینی1. Train the predictorمهاجم پیش‌بینی شاخه را هدایت می‌کندattacker steers branch prediction
۲. اجرای حدسی2. Speculative runدستورهای مسیر پیش‌بینی‌شده اجرا می‌شوندpredicted path runs
۳. تغییر Cache3. Cache changesوضعیت کش عوض می‌شودcache state changes
۴. اندازه‌گیری زمان4. Time the accessاستنباط اطلاعات از زمان دسترسیinfer data from timing

نکته: حتی اگر نتایج معماری کنار گذاشته شوند، آثار جانبی ممکن است بمانند.Note: even if architectural results are discarded, side effects may remain.

راهکارهای مقابلهMitigationsبه‌روزرسانی سیستم‌عامل و میکروکد، اصلاح نرم‌افزارهای آسیب‌پذیر و روش‌های سخت‌افزاری و نرم‌افزاری برای محدودکردن اجرای حدسی خطرناک.Update the OS and microcode, fix vulnerable software, and use hardware and software methods that limit risky speculation.

آسیب‌پذیری MeltdownThe Meltdown vulnerability

Meltdown چیست؟What is Meltdown?حمله‌ای که در پردازنده‌های آسیب‌پذیر از اجرای موقت دسترسی‌های حافظه و نحوهٔ مدیریت مجوزها استفاده می‌کند تا اطلاعاتی را که برنامه نباید ببیند استنباط کند.An attack that, on vulnerable CPUs, abuses temporary execution of memory accesses and permission handling to infer data a program must not see.
۱. خواندن غیرمجاز1. Forbidden readبرنامه داده‌ای بدون مجوز می‌خواندprogram reads data without permission
۲. اجرای موقت2. Temporary runپیش از نهایی‌شدن بررسی مجوزbefore the permission check finishes
۳. تغییر Cache3. Cache changesبر اساس دادهٔ محافظت‌شدهbased on the protected data
۴. تحلیل زمان4. Timing analysisاستنباط مقدار دادهinfer the value
تفاوت با SpectreDifference from SpectreSpectre از پیش‌بینی شاخه و مسیر گمراه‌کننده بهره می‌گیرد؛ Meltdown کلاسیک از اجرای موقت دسترسی حافظه‌ای که باید رد شود. همهٔ پردازنده‌ها به همهٔ گونه‌ها آسیب‌پذیر نیستند.Spectre exploits branch prediction; classic Meltdown exploits temporary execution of a memory access that should be rejected. Not every CPU is vulnerable to every variant.
راهکارهای مقابلهMitigationsبه‌روزرسانی سیستم‌عامل و میکروکد، اصلاحات متناسب با پردازنده و جداسازی حافظهٔ هسته از فضای کاربر (مثل KPTI).OS and microcode updates, CPU-specific fixes, and better isolation of kernel memory from user space (e.g. KPTI).

جمع‌بندیSummary

  • دستورهای مستقل می‌توانند خارج از ترتیب اولیه اجرا شوند.Independent instructions can execute outside the original order.
  • تغییر نام ثبات‌ها وابستگی‌های نامی را حذف می‌کند.Register renaming removes name dependencies.
  • وابستگی‌های واقعی داده همچنان رعایت می‌شوند.True data dependencies are still respected.
  • نتایج به ترتیب برنامه تأیید نهایی می‌شوند.Results are committed in program order.
جمع‌بندی نهاییFinal summaryOOO عملکرد را بهتر می‌کند، اما پیچیدگی و مصرف انرژی را بالا می‌برد و در کنار اجرای حدسی ملاحظات امنیتی مهمی دارد.OOO improves performance, but adds complexity and energy use, and together with speculation brings important security concerns.

Out-of-Order Execution: اجرای انعطاف‌پذیر، نتیجهٔ صحیح.Out-of-Order Execution: flexible execution, correct result.

پرسشQuestion

فرض کنید دستورهای زیر به ترتیب در برنامه قرار دارند:Suppose these instructions appear in this order in a program:

I1: ADD R1, R2, R3
I2: SUB R4, R5, R6
I3: ADD R7, R1, R4
  • آیا دستور I2 می‌تواند قبل از I1 اجرا شود؟ چرا؟Can I2 execute before I1? Why?
  • آیا I3 می‌تواند قبل از هر دو دستور I1 و I2 اجرا شود؟Can I3 execute before both I1 and I2?
  • آیا اجرای خارج از ترتیب به معنی تغییر ترتیب نهایی دستورهاست؟Does out-of-order execution change the final order of the instructions?
راهنماHintوابستگی داده‌ای میان دستورها و آماده‌بودن عملوندها را بررسی کنید. مستقل‌بودن دو دستور می‌تواند اجرای خارج از ترتیب را ممکن کند.Check the data dependencies and whether operands are ready. Two independent instructions may execute out of order.

پاسخ پرسشAnswer

۱. بله1. YesI2 به نتیجهٔ I1 وابسته نیست؛ اگر منابع آماده باشند، زودتر اجرا می‌شود.I2 does not depend on I1; if resources are free, it can run earlier.
۲. خیر2. NoI3 از R1 و R4 استفاده می‌کند، پس باید منتظر نتایج هر دو بماند.I3 uses R1 and R4, so it must wait for both results.
۳. خیر3. Noترتیب اجرا عوض می‌شود، اما با نهایی‌سازی مرتب، دستورها به ترتیب اصلی Commit می‌شوند.Execution order can change, but with in-order finalization instructions commit in the original order.

نکتهٔ کلیدی: پردازنده دستورهای مستقل را زودتر اجرا می‌کند، اما وابستگی‌های واقعی را نادیده نمی‌گیرد.Key point: the CPU runs independent instructions earlier but never ignores true dependencies.
